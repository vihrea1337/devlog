# История изменений

Формат — по мотивам [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/): сверху новое.
Версии Android-приложения — `versionName` в `androidApp/app/build.gradle.kts`.

## 2026-10-19 (вечер) — отчёты за день, неделю и месяц сами

### Добавлено
- **Автоматика отчётов** (панель «Автоматика» в вебе, `GET/PUT /api/automation`, миграция V10):
  сервер сам собирает «Отчёт работодателю» — **за день** (утром за вчера), **за неделю** (в
  понедельник за прошлую) и **черновик месяца** (в последний день месяца после 12:00). Каждый
  вид включается отдельно, всё — по часовому поясу пользователя; пропущенное догоняется.
  Отчёты помечены «собран сам». Кнопки «Собрать сейчас»: за сегодня / эту неделю / этот месяц.
- **Месяц в два шага сам**: недели берутся из готовых недельных отчётов (их могли поправить)
  или пишутся ИИ по записям недели, затем месяц — из недель; пауза между запросами под лимит
  бесплатного Groq. В месячном отчёте — раздел «По неделям» («Кратко» каждой недели).
- **Коммиты с сервера раз в сутки**: импорт GitHub «один репозиторий» за последние 7 дней с
  привязанным токеном (для чужого приватного репозитория — classic с правом `repo`).
- **Коммиты с ПК без токена GitHub**: `push-day-files.mjs --git <копия репозитория>` читает
  `git log` (только чтение) и отправляет коммиты в `POST /api/import/commits`. Записи те же,
  что у импорта GitHub, — способы можно чередовать без дублей.
- **Уведомление Windows о готовом отчёте**: `push-day-files.mjs --notify` спрашивает
  `GET /api/import/notices` и показывает всплывающее уведомление (нажатие открывает отчёт).
- Проект для скрипта можно задать именем: `--project-name Weather`.
- Образец отчёта — `docs/employer-report-sample.md`.

### Изменено
- «Отчёт работодателю»: строка «Исполнитель · Проект · Составлен» под периодом и подпись внизу;
  при коммитах из GitHub строка «Коммитов» из записей дня больше не дублируется; у отчёта за
  один день нет хронологии, заголовок — «Отчёт за 18 октября 2026».
- Импорт GitHub «один репозиторий» относит коммит к дню по поясу из «Автоматики» (ночной коммит
  по Москве больше не уезжает во вчера по UTC); без настроек — UTC, как раньше.
- Месяц «из недельных отчётов» не принимает отчёты за один день за неделю.

## 2026-10-19 — отчёты работодателю из файлов дня

### Добавлено
- **Импорт файлов дня** (`POST /api/import/day-files`, панель «Файлы дня» в вебе): файлы
  `ГГГГ-ММ-ДД.md` по одному или папкой месяца. Дата — из имени файла, один файл — одна запись.
  Разделы «Сделано / Проверено / Нехватки / Не делалось / Цифры» разбирает **код, а не ИИ** —
  запись сразу готова, текст никуда не отправляется. Файл дописали — загрузите снова: запись
  обновится; если её правили в DevLog — не затрётся (заменить можно флажком «Перезаписать»).
- **Шаблон «Отчёт работодателю»**: Кратко / Сделано (по темам) / Проверено / Передано другим и
  нехватки / Не сделано и почему; «Цифры периода» складываются кодом из разделов «Цифры»
  записей дня (коммиты и сборки — сумма, тесты «к концу дня» — было → стало); хронология с числом
  коммитов за день. Без ИИ собирается целиком кодом.
- **Месяц из недельных отчётов** (флажок «Из недельных отчётов»): в ИИ уходят уже вычитанные
  недели, а не 100+ тысяч знаков записей — точнее и влезает в лимит бесплатного Groq.
- **Токены для скриптов и автоимпорт с ПК**: в «Файлах дня» выпускается токен, который умеет
  только импорт (хранится хешем, отзывается кнопкой); скрипт `tools/push-day-files.mjs` отправляет
  папку записей — вручную, Планировщиком заданий или хуком Claude Code (`--hook`: только что
  записанный файл). Инструкция — `docs/auto-import.md`. Миграция V9.
- **Импорт GitHub: режим «один репозиторий»** — коммиты автора прямо из репозитория, без лимита
  ~90 дней ленты событий, в том числе из чужого приватного (с classic-токеном `repo`).

### Изменено
- Импорт GitHub берёт не только первую строку коммита, но и описание: при Conventional Commits
  первая строка — просто `feat(android)`. Повторный импорт дописывает в день новые коммиты.

### Исправлено
- Правка записи из файла дня и «Переобработать» разбирают её заново кодом, а не отправляют в ИИ.
- Лог старта писал «Схема БД актуальна (версия 1)» на базе любой версии — теперь настоящую версию.
- **Утечка в Groq:** импорт GitHub/GitLab/текста в проект с выключенным ИИ ставил записи в
  очередь ИИ, и воркер отправлял их текст в Groq. Теперь статус решается при создании записи
  (сразу «черновик»), а воркер перед отправкой ещё раз проверяет выключатель проекта — в том
  числе если его выключили, когда записи уже ждали обработки.

## 2026-10-11 — Android 1.3.1: один HTTP-клиент

### Изменено
- **Retrofit убран, всё приложение ходит в сеть через Ktor Client.** Раньше их было два: Retrofit
  (вход, отчёты, профиль, проекты) и Ktor из `shared/` (синхронизация записей) — два клиента с
  разной обработкой ошибок. Теперь одна цепочка: OkHttpClient (таймауты, токен, 401 → выход) →
  движок Ktor → `DevLogApi` и клиент синхронизации на одном движке. Ответ 4xx/5xx превращается в
  `ApiException` (код + причина из тела ответа) в одном месте — `HttpResponseValidator`.
- Пустая неделя в ленте — «последняя запись N дней назад»; адрес сервера из `BuildConfig`
  (сделано ночью 10→11 октября, впервые попадает в APK на сайте).

### Исправлено
- Неверный пароль при входе показывал «Сессия истекла — войдите заново» (любой 401 считался
  истёкшим токеном). Теперь показывается причина от сервера: «Неверный email или пароль».

## 2026-10-10 (ночь) — витрина: новый веб, публичный отчёт, Android 1.3.0

### Добавлено
- **Демо-вход «только для просмотра»** — кнопка «Открыть демо» в вебе и в Android: готовый дневник
  без регистрации. Сервер выдаёт токен readOnly и сам отклоняет любые изменения (403), клиенты
  прячут кнопки изменений. Включается переменной `DEMO_LOGIN_EMAIL`.
- **Android 1.3.0:** сводка последних 7 дней в ленте, мерцающая заглушка «ИИ разбирает запись…»
  и подсветка только что разобранной записи, голосовой ввод (системное распознавание речи),
  подсказки по шагам во время сборки отчёта, «Куда уходит время» в профиле (кольцо по проектам
  на Canvas и частые темы), вибрация при сохранении и удалении.
- **Публичная страница отчёта как документ:** обложка, плитки цифр, график активности по неделям,
  линия времени, превью ссылки для мессенджеров (Open Graph), печать в PDF.
- README со скриншотами Android и веба; юнит-тесты расчётов сводки недели, «Куда уходит время» и
  демо-входа (Android — 17 тестов).

### Изменено
- **Веб заново:** экран входа с описанием продукта, две колонки (лента + сводка/календарь/действия),
  карточки записей как в Android, модальные панели, мобильная вёрстка, «Показать ещё».
- Отчёт по одному проекту по умолчанию называется по проекту: «DevLog: отчёт за октябрь 2026».

### Исправлено
- «Куда уходит время»: записи удалённого проекта давали вторую строку «Без проекта».
- Сводка недели показывала «0 ч», если учтено меньше часа; «1 часов» в профиле.
- Во время сборки отчёта кнопка становилась серой и подсказки было не прочитать.

## 2026-10-10 (вечер) — Android 1.2.0 и точность ИИ

### Изменено
- **Android переписан под современный стек:** Hilt (DI), репозитории-интерфейсы, Navigation
  Compose с типобезопасными маршрутами, синхронизация через WorkManager (офлайн-записи уезжают
  при появлении сети даже при закрытом приложении), выход на экран входа при 401.
- **Новый интерфейс:** своя тема (светлая/тёмная), нижние вкладки «Лента / Отчёты / Профиль»,
  окно новой записи с календарём, проектом и временем, pull-to-refresh, удаление с «Отменить»,
  раскрывающиеся карточки, профиль с календарём активности, импорт коммитов GitHub, вечернее
  напоминание, адаптивная иконка и заставка.
- Release-сборка с R8: APK ~2 МБ вместо ~12. Токен не уходит в облачную резервную копию.
- **ИИ:** записи разбирает `gpt-oss-120b` (20b путала факты: план выдавала за сделанное, «треть
  записей» — за «третью запись», часть записей — по-английски); новый промпт; отчёт опирается на
  исходные заметки, а не только на их разбор; пустой ответ модели (finish_reason=length) —
  повтор с меньшим reasoning_effort.
- Заголовок отчёта по умолчанию — «Отчёт за 4–10 октября 2026» вместо ISO-дат.

### Исправлено
- **Android: синхронизация с сервером по HTTPS не работала в раздаваемой сборке** — Ktor CIO
  делал TLS сам и падал на network_security_config; теперь движок OkHttp (TLS платформы).
- Тёмная тема: невидимый заголовок на экране входа; склонение («1 день подряд»).
- Календарь активности считал удалённые записи.

### Добавлено
- Юнит-тесты ViewModel (JUnit + Turbine) в CI; скрипт демо-аккаунта `deploy/demo/seed.mjs`.

## 2026-10-10 — переезд и качество отчётов (Android 1.1.0)

### Изменено
- **Отчёт пишется по темам, а не по дням.** Раньше ИИ получал черновик «по дням, списком шагов»
  (решения и проблемы туда не попадали вовсе) с задачей «перепиши, сохрани все даты» — и возвращал
  тот же список. Теперь ИИ получает полную структуру записей и пишет разделы «Кратко», «Главные
  результаты», «Ключевые решения», «Сложные проблемы», «Что дальше»; «Цифры периода» и
  «Хронологию» (одна строка на день) считает код.
- Отдельная модель для отчётов `GROQ_REPORT_MODEL` (по умолчанию `openai/gpt-oss-120b`) с откатом
  на основную; бюджет токенов подобран под лимит бесплатного Groq (8000 токенов/мин).
- Промпт разбора записи: решения в форме «что выбрал — почему», проблемы «что сломалось →
  причина → решение», меры предосторожности — не проблемы, без канцелярита.
- Переезд на новый сервер (`/opt/devlog`, общий с другими проектами, свой порт 34444).

### Исправлено
- Ответ 429 от Groq больше не делает запись `failed`: она ждёт без траты попытки, воркер
  выдерживает паузу по `retry-after` (раньше при импорте пачкой падала треть записей).
- Строгий JSON-режим Groq иногда отвергал ответ модели (400 `json_validate_failed`) — теперь
  повтор без строгого режима.
- **Утечка:** записи проектов с выключенным ИИ уходили в Groq при сборке отчёта.
- Одновременные регистрации одного email давали 500 вместо 409.
- Markdown: `код` в отчётах, нумерованные списки; `snake_case` больше не становится курсивом.
- Android: офлайн-очередь сама уезжает на сервер при появлении сети; экран входа показывает
  настоящую причину ошибки (короткий пароль, занятый email, нет связи).

### Добавлено
- Страница о сервисе и установки `/install.html`, «Конфиденциальность» и «Условия использования»;
  `/demo` — пример отчёта; APK раздаётся с сервера (`/download/DevLog.apk`).
- CI: смоук-тест настоящего Docker-образа на Postgres — все миграции Flyway применены, сквозной
  сценарий API (регистрация → запись → отчёт → публичная ссылка). Release по тегу (APK +
  дистрибутив), Deploy по кнопке через SSH.
- `SECURITY.md`, `CHANGELOG.md`, `LICENSE`.
