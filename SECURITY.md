# Безопасность DevLog

Коротко и честно: как устроен доступ, где лежат секреты, что уходит третьим сторонам и какие
у проекта известные слабые места. Для пользователей то же самое — на странице `/privacy.html`.

## Как сообщить об уязвимости

Через GitHub: вкладка **Security → Report a vulnerability** (приватное сообщение автору), либо
лично автору ([github.com/vihrea1337](https://github.com/vihrea1337)). Просьба не публиковать
подробности, пока исправление не выкачено.

## Доступ и аккаунты

- Вход по email и паролю; пароль хранится только как хэш **bcrypt**.
- Сервер выдаёт **JWT** (подписанный токен) — клиенты шлют его в `Authorization: Bearer`.
  Сервер **отказывается стартовать** с дефолтным секретом подписи — прод не поднимется
  с секретом из репозитория.
- **Изоляция пользователей:** каждый запрос к записям, проектам и отчётам фильтруется по
  владельцу; чужой id → 404, а не чужие данные (покрыто интеграционными тестами).
- **Публичная ссылка на отчёт** — случайный токен (UUID, 122 случайных бита); отчёт помечен `noindex`,
  ссылку можно отозвать.

## Секреты

- В git не попадают: `backend/secrets.properties` (локально), на сервере — `.env` и
  `devlog.env` (`JWT_SECRET`, `GROQ_API_KEY`, пароль БД, токен DuckDNS).
- Личные токены GitHub/GitLab пользователей хранятся зашифрованными (**AES-GCM**, ключ
  выводится из `JWT_SECRET`), в логи не пишутся и через API не возвращаются — только
  признак «привязан».

## Что уходит третьим сторонам

- **Groq** — текст записи (для разбора) и структура записей за период (для отчёта). Для
  проектов с **выключенным ИИ** не уходит ничего — ни при разборе, ни при сборке отчёта
  (до 2026-10-10 при сборке отчёта уходили первые строки таких записей — исправлено).
- **GitHub/GitLab** — запросы от имени пользователя с его токеном, только по его действию.

## Транспорт и инфраструктура

- Наружу открыт только Caddy (HTTPS, Let's Encrypt через DNS-проверку DuckDNS). Бэкенд и
  Postgres — во внутренней docker-сети.
- CI проверяет настоящий Docker-образ на Postgres: применились ли **все** миграции — однажды
  сборка молча теряла их, и сервер работал на пустой схеме.

## Известные слабые места (осознанно, для pet-проекта)

- **Нет ограничения частоты входа** (rate limiting) — перебор паролей упирается только в
  стоимость bcrypt.
- **JWT нельзя отозвать** до истечения срока — нет списка отозванных токенов.
- **Удаление аккаунта** — только по запросу владельцу сервиса; удалённые записи хранятся
  с пометкой (нужно для синхронизации устройств) и физически не стираются.
- **Регистрация открыта всем**, подтверждения email нет.
- **APK подписан debug-ключом** и раздаётся с сайта, не через Google Play.
- Тексты от ИИ могут быть неточными — отчёт перед отправкой стоит перечитать (его можно править).
