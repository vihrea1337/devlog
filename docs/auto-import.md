# Автоимпорт и отчёты сами

Как сделать, чтобы файлы дня (`ГГГГ-ММ-ДД.md` с разделами «Сделано», «Проверено», «Нехватки»,
«Не делалось», «Цифры») и коммиты сами попадали в DevLog, а отчёты за день, неделю и месяц
собирались без кнопок.

Две половины:
- **ПК** отправляет файлы дня и коммиты (сервер к папкам на ПК доступа не имеет) — скрипт
  `tools/push-day-files.mjs` (Node 18+, без зависимостей), раз в час Планировщиком заданий;
- **сервер** собирает отчёты по расписанию — панель «Автоматика» в вебе.

Повторная отправка ничего не дублирует, а запись, которую вы правили в DevLog руками, скрипт
не затрёт.

> **Перед тем как включать:** если записи — о работе на работодателя, убедитесь, что
> отправлять их в DevLog и во внешний ИИ (Groq) можно. Нельзя в ИИ — выключите ИИ у проекта
> (Проекты → «ИИ выкл.»): разделы файлов дня разбирает код, отчёт тоже соберёт код.

## 1. Токен для скрипта

Веб DevLog → «Файлы дня» → «Токен для скриптов» → назовите («Домашний ПК») → «Выпустить».
Токен показывается **один раз** — скопируйте. Он умеет только импорт (файлы дня, текст,
коммиты) и узнавать о готовых отчётах (только названия): читать, удалять, делиться отчётами
им нельзя. Потерялся или больше не нужен — «Отозвать».

Положите токен в переменную окружения пользователя Windows (не в файлы и не в репозиторий):

```powershell
[Environment]::SetEnvironmentVariable("DEVLOG_IMPORT_TOKEN", "dli_…", "User")
```

Проект задаётся именем (`--project-name Weather`, без учёта регистра) или id (`--project <id>`).

## 2. Коммиты: с токеном GitHub или без

- **Без токена (с ПК).** `--git "C:\путь\к\копии"` — скрипт читает `git log` вашей локальной
  копии (только чтение, в репозитории ничего не меняется) и отправляет коммиты. Работает и для
  чужого приватного репозитория — копия у вас уже есть. Репозиторий — из адреса `origin`
  (или `--repo владелец/имя`), автор — `git config user.email` этой копии (или `--author`).
  Коммиты, которые ещё не скачаны в копию (`git pull`), скрипт не видит — свои вы и так делаете в ней.
- **С токеном (с сервера).** В «Импорте с GitHub» укажите логин и привяжите токен; для чужого
  приватного репозитория — **classic** с правом `repo` (fine-grained к чужому личному
  репозиторию доступа не даёт). В «Автоматике» впишите репозиторий — сервер будет забирать
  коммиты раз в сутки после 04:00. ПК для этого не нужен.

Оба способа дают одни и те же записи (одна на репозиторий и день) — можно включить оба.

## 3. Проверка руками

```powershell
node tools\push-day-files.mjs --dir "C:\путь\к\записям" --git "C:\путь\к\копии" --project-name Weather --dry-run
node tools\push-day-files.mjs --dir "C:\путь\к\записям" --git "C:\путь\к\копии" --project-name Weather --notify
```

`--dry-run` только показывает, что уйдёт. По умолчанию берутся последние 45 дней (`--days`).
Коды возврата: 0 — отправлено, 1 — сервер/сеть/git не ответили, 2 — неверные аргументы.

## 4. Раз в час — Планировщик заданий Windows

```powershell
$node = (Get-Command node).Source
$args = 'C:\Users\<вы>\Desktop\Projects\devlog\tools\push-day-files.mjs --dir "C:\путь\к\записям" --git "C:\путь\к\копии" --project-name Weather --days 14 --notify'
$action   = New-ScheduledTaskAction -Execute $node -Argument $args
$trigger  = New-ScheduledTaskTrigger -Once -At (Get-Date) -RepetitionInterval (New-TimeSpan -Hours 1)
$settings = New-ScheduledTaskSettingsSet -StartWhenAvailable -DontStopIfGoingOnBatteries -AllowStartIfOnBatteries
Register-ScheduledTask -TaskName "DevLog — автоимпорт" -Action $action -Trigger $trigger -Settings $settings
```

`--notify` показывает уведомление Windows, когда автоматика собрала новый отчёт: нажатие
открывает его в браузере. Показанные запоминаются в `%LOCALAPPDATA%\DevLog\notified.json`.

## 5. Отчёты сами — «Автоматика» в вебе

Выберите проект, часовой пояс и какие отчёты собирать:

| Отчёт | Когда | За что |
|---|---|---|
| За день | каждое утро после 04:00 | за вчера (файл дня дописывается до ночи) |
| За неделю | в понедельник после 04:00 | за прошлую неделю, пн–вс |
| За месяц | в последний день месяца после 12:00 | черновик за месяц: недели → месяц |

Месяц собирается в два шага: готовые недельные отчёты (их могли поправить руками) берутся как
есть, недостающие недели ИИ пишет по записям, затем из недель — месяц. Пустой период отчёта не
даёт. Сервер был выключен — неделя догоняется в любой день следующей, месяц — в первые 3 дня.
«Собрать сейчас» — отчёт по сегодняшний день, не дожидаясь расписания. Образец того, как
выглядит отчёт, — `docs/employer-report-sample.md`.

## 6. Сразу после записи — хук Claude Code (по желанию)

Если файлы дня пишет Claude Code, хук `PostToolUse` отправит файл сразу после записи.
В режиме `--hook` скрипт читает JSON о записанном файле со входа и отправляет **только его**
и только если файл лежит в `--dir` и в имени есть дата — остальные правки пропускает молча.
Коммиты и уведомления в этом режиме не трогаются — их делает задача Планировщика.

В `.claude/settings.json` той папки, где пишутся записи (или в пользовательских настройках):

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [
          {
            "type": "command",
            "command": "node C:/Users/<вы>/Desktop/Projects/devlog/tools/push-day-files.mjs --hook --dir \"C:/путь/к/записям\" --project-name Weather"
          }
        ]
      }
    ]
  }
}
```

Токен хук берёт из той же переменной `DEVLOG_IMPORT_TOKEN`.
