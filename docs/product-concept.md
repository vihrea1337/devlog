# DevLog — концепция продукта

## Проблема
У разработчика не остаётся внятной истории того, что он делал: есть только коммиты
в GitHub (сухие, без контекста «почему» и «что решил»). Когда нужно отчитаться перед
работодателем за месяц или вспомнить свой путь для резюме — восстановить это тяжело.
Вести дневник вручную дисциплинированно почти никто не может.

## Решение
Сервис принимает **сырые заметки** о проделанной за день работе (введённые руками
или взятые из работы с ИИ-ассистентом) и с помощью ИИ превращает их в **структурированную
летопись**: даты, шаги, принятые решения, решённые проблемы, итоги. Из записей за период
собирается **красивый отчёт** (Markdown/PDF/ссылка), который можно отдать работодателю.

Порог входа низкий: бросить в конце дня огрызок текста — легко; структуру добирает ИИ.

## Понятия предметной области
- **Запись (Entry)** — единица работы за конкретный день: сырой текст + метаданные
  (дата, проект, потраченное время, источник).
- **Структурированная запись** — то, что ИИ извлёк из сырого текста:
  краткая суть, список шагов, принятые решения, решённые проблемы, итог, теги.
  Сырьё сохраняется всегда — структуру можно перегенерировать.
- **Проект (Project)** — группировка записей (например «Работа в компании X», «SkyCast»).
- **Отчёт (Report)** — агрегат записей за период (неделя/месяц), собранный ИИ в связный
  документ. Можно поделиться по ссылке (для работодателя, без входа в систему).
- **Пользователь (User)** — аккаунт; каждый видит только свои данные.

## Ключевые фичи
**MVP (Фаза 1):** ввод сырой заметки → ИИ структурирует → лента записей по дням →
генерация отчёта за месяц → экспорт в Markdown. С аккаунтами (регистрация/вход).

**Дальше:** экспорт в PDF, шаринг отчёта по ссылке, несколько проектов, мобильное
приложение (Android → iOS → Desktop), офлайн.

## Киллер-фича — импорт сырья
Главное отличие от блокнота: сырьё можно не только печатать руками.
- **GitHub/GitLab:** подтягиваем коммиты за день как исходный материал для ИИ.
  «Нет истории кроме коммитов» превращается в «коммиты сами становятся дневником».
- **Выгрузки из чатов / Claude Code:** текст рабочей сессии с ИИ-ассистентом — готовое
  сырьё, из которого ИИ вытащит суть сделанного.

## Чего НЕ делаем рано (защита от расползания)
- Не строим сразу 4 отдельных приложения — начинаем с веба.
- Не делаем биллинг/тарифы на старте (архитектура готова к ним, но это Фаза 4+).
- Не пилим таск-трекер/канбан — это дневник постфактум, а не планировщик.

## Кто пользователь
Разработчики (и шире — любые айтишники), которым нужно регулярно отчитываться
о проделанной работе или вести профессиональную летопись для себя и резюме.
