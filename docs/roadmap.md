Сердцевина продукта. Сценарий целиком в браузере.
- [x] Таблицы БД на Exposed (`Tables.kt`) + подключение (`Database.kt`) + `docker-compose.yml` — компилируется, фэт-джар собирается. _Живая проверка (создание таблиц в БД) — после `docker compose up` (Docker был выключен)._
- [x] JWT-авторизация: регистрация, вход, `GET /api/me` (bcrypt-хеш пароля, JWT-токен). Покрыто интеграционными тестами на H2 (4 теста) — зелёные.
- [x] CRUD записей (`/api/entries`, per-user, изоляция пользователей) — 5 тестов на H2 зелёные
- [x] Фоновая обработка ИИ — заготовка на **Groq** (OpenAI-совместимый; `AiProcessor` + `EntryStructuredRepository`, строгий JSON, статусы queued→processing→structured/failed). Юнит-тесты разбора + интеграционный на H2 зелёные. **Осталось: вставить ключ Groq** в `backend/secrets.properties` (`groq.api.key`)
- [x] Генерация отчёта за период (`/api/reports`): детерминированный черновик Markdown + ИИ-причёсывание (если есть ключ), шаринг по ссылке `/r/{token}` (публичная HTML-страница), скачивание .md на вебе — 4 теста на H2 зелёные
- [x] Веб-страница от бэкенда (`resources/static/index.html`): вход/регистрация, форма записи, лента по дням со статусами и структурой ИИ, авто-обновление пока идёт обработка. _Кнопка «отчёт за месяц» — после эндпоинта отчётов._
- [x] Лимиты ИИ на пользователя (`AiLimiter`: суточный, env `AI_DAILY_LIMIT`=200; 2 юнит-теста)
- **Готово (в коде + 20 тестов на H2):** можно зарегистрироваться, добавить заметку, получить
  структуру и собрать/скачать отчёт за месяц — в браузере. **Осталось прогнать вживую на Postgres.**

## Фаза 3.5 — Фундамент (2026-08-12)
Блок «сначала чиним фундамент, потом добавляем фичи»: до этого любое изменение схемы
не доехало бы до прода, а обработка ИИ терялась при каждом перезапуске сервера.
- [x] Миграции схемы Flyway вместо `SchemaUtils.create` + тест-страховка от расхождения
      миграций и `Tables.kt` (`SchemaMigrationTest`)
- [x] `AiWorker`: очередь обработки живёт в базе — переживает перезапуск, подбирает
      зависшие записи, считает попытки, сохраняет причину ошибки (`ai_error`), уважает
      суточный лимит (8 тестов)
- [x] `GET /api/config` + веб: честное «ИИ выключен» вместо вечного «в очереди»
- [x] Проверка владения проектом (закрыт обход чужого выключателя ИИ)
- [x] Валидация запросов: 400 с объяснением вместо 500, потолок длины заметки
- [x] Отказ старта на внешнем адресе без `JWT_SECRET`; `noindex` на публичном отчёте
- [x] Правка текста записи возвращает её в очередь на переобработку
- [ ] Живая проверка на Postgres (нужен запущенный Docker) и редеплой на сервер

## Фаза 3.6 — UX веба (2026-08-12)
Продукт должен войти в привычку, а для этого ввод обязан быть мгновенным,
а результат — наглядным.
- [x] Ввод: черновик в localStorage (закрытая вкладка больше не съедает текст),
      Ctrl+Enter, автофокус, счётчик символов
- [x] Правка записи прямо в карточке (в API это было с самого начала, кнопки не хватало)
- [x] Календарь активности за год + серия дней подряд (`GET /api/stats/activity`)
- [x] Человеческие заголовки дней и **исправленный сдвиг дат** (`toISOString()` отдаёт UTC,
      восточнее Лондона дата съезжала на день назад)
- [x] Поиск по записям и структуре ИИ, кликабельные теги, чипы активных фильтров
- [x] Отчёты: любой период, предпросмотр готовым HTML, правка текста, история отчётов,
      отзыв публичной ссылки, «Печать / PDF»
- [x] Тёмная тема (по умолчанию — как в системе)
- [x] PDF: печатью браузера. Серверная генерация потребовала бы встроенного шрифта
      с кириллицей (~700 КБ в репозитории) — пока не нужно
